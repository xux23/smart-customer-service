## 1. 技术选型与理由

| 技术 | 用途 | 选择理由 |
|---|---|---|
| Python 3.12 | 开发语言 | 生态成熟，AI 项目事实标准 |
| uv | 环境与依赖管理 | 快、锁版本、一条命令装齐，替代 venv + pip |
| FastAPI + uvicorn | REST 接口 | 自带请求校验（Pydantic）和交互式文档（/docs），代码量少 |
| openai SDK | 调用大模型 | OpenAI 兼容协议，换智谱/DeepSeek/通义只改 base_url 和模型名 |
| jieba | 中文分词 | 纯本地、稳定，TF-IDF 的前置步骤 |
| sqlite3（标准库） | 工单存储 | 零部署、单文件；不用 ORM，裸 SQL 更直观 |
| pytest | 单元测试 | 简单通用，配合 Mock 保证测试不碰网络 |
| httpx | CLI 调接口 + 接口测试 | 同时支持 requests 风格和 ASGI 直连（TestClient） |

## 2. 环境搭建（uv）

```bash
# 0. 确认已安装 uv（https://docs.astral.sh/uv/）
uv --version

# 1. 在项目根目录初始化
uv init .

# 2. 安装运行依赖
uv add fastapi "uvicorn[standard]" openai jieba python-dotenv

# 3. 安装开发依赖
uv add --dev pytest httpx

# 4. 配置环境变量
cp .env.example .env     # Windows Git Bash；PowerShell 用 Copy-Item
#    编辑 .env 填入 LLM_API_KEY；不填并把 LLM_PROVIDER 改为 mock 也能跑

# 5. 启动服务
uv run uvicorn app.main:app --reload --port 8000

# 6. 命令行演示（另开一个终端）
uv run python scripts/chat_cli.py

# 7. 跑测试
uv run pytest
```

## 4. 配置项说明

`.env.example` 全部字段：

| 变量 | 默认值 | 说明 |
|---|---|---|
| LLM_PROVIDER | openai | `openai` = 真实接口；`mock` = 规则模拟，离线可跑 |
| LLM_BASE_URL | 智谱地址 | OpenAI 兼容接口地址，见下表 |
| LLM_API_KEY | （空） | 为空时自动降级为 mock 模式并打日志警告 |
| LLM_MODEL | glm-4-flash | 模型名 |
| INTENT_CONFIDENCE_THRESHOLD | 0.6 | 意图置信度阈值，低于转人工 |
| KB_MATCH_THRESHOLD | 0.55 | 检索直接回答阈值 |
| KB_SIMILAR_THRESHOLD | 0.30 | 相似问题列表下限阈值 |
| KB_TOP_N | 3 | 降级时返回的相似问题数量 |
| KB_PATH | app/data/knowledge.json | 知识库文件路径 |
| DB_PATH | tickets.db | SQLite 文件路径 |

常用服务商 `LLM_BASE_URL` / `LLM_MODEL` 对照：

| 服务商 | LLM_BASE_URL | LLM_MODEL 示例 |
|---|---|---|
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |

## 5. 模块实现要点

> 以下代码为示意（表达结构和写法风格），以实际实现为准。风格要求：朴素直白，普通函数 + 字典 + for/if，不用炫技语法。

### 5.1 app/config.py

- `python-dotenv` 加载 `.env`，用 `@dataclass` 定义 `Settings`；
- 提供 `get_settings()` 返回单例；
- 所有模块只从这里读配置，不直接碰环境变量。

### 5.2 app/core/llm.py

两种客户端 + 一个工厂：

```python
class OpenAIClient:
    """OpenAI 兼容接口的薄封装，只暴露 chat 一个方法"""
    def chat(self, system_prompt, user_prompt) -> str: ...

class MockLLMClient:
    """关键词规则模拟意图识别，返回固定格式 JSON，测试和离线演示用"""
    def chat(self, system_prompt, user_prompt) -> str: ...

def create_llm_client():
    if settings.llm_provider == "mock" or not settings.llm_api_key:
        return MockLLMClient()
    return OpenAIClient()
```

注意：`OpenAIClient.chat` 内部**不做重试**，重试属于意图 Agent 的兜底链职责；LLM 层只负责"调一次、返回文本或抛异常"，职责单一。

## 7. 测试方案

- **原则：测试不碰网络。** `conftest.py` 里强制 `LLM_PROVIDER=mock`，真实 LLM 的行为差异靠演示环节人工验证；
- Mock LLM 与关键词兜底词典同源，保证"mock 模式"和"兜底链"行为一致；
- 状态机、TF-IDF、阈值路由是纯函数/纯逻辑，直接断言输入输出；
- 接口测试用 `fastapi.testclient`（基于 httpx，ASGI 直连，不用起服务）。

## 9. 代码风格约定

1. 命名用完整英文单词，函数动词开头（`create_ticket`、`build_index`）；
2. 只用普通函数、字典、dataclass、for/if；不用装饰器（FastAPI 路由除外）、生成器表达式嵌套、元类等炫技写法；
3. 单文件不超过 200 行，函数尽量不超过 30 行；
4. 注释只写"为什么这么做"，不写"这行在干什么"；
5. 类型标注用基础类型（`str`、`dict`、`list[str]`），让读代码的人一眼看懂数据形状。

## 10. 面试讲解要点

### 亮点 1：意图分类 = Prompt 约束 + 四级兜底链

> "LLM 是不可控的外部依赖，所以我做了约束和兜底两层。约束是在 Prompt 里限定四个枚举值、给 few-shot 示例、要求只输出 JSON；兜底是四级链路：解析失败就把报错拼回 Prompt 重试一次，再失败走关键词规则，网络异常直接走关键词规则，兜底结果置信度固定 0.4，低于 0.6 的转人工阈值，等于'兜底出来的分类默认不被信任'。整个链路保证任何情况下意图识别都不会抛异常中断对话。"

追问预案：置信度是模型自评不是真概率 → 承认局限，说明实测有区分度，严格做法是多次采样投票，属于扩展项。

### 亮点 2：检索失败的降级方案

> "知识库检索用 TF-IDF 余弦相似度，关键是三级阈值路由：0.55 以上直接回答，0.30 到 0.55 之间不硬答，返回 top3 相似问题让用户自己选，0.30 以下直接建工单转人工。设计思想是每一层都保留'承认解决不了'的出口，从机制上避免检索到不相关内容还硬编一个回答的幻觉问题。"

追问预案：为什么不用向量检索 → 十几条数据 TF-IDF 够用、零依赖、可解释；数据量上来换 embedding，检索模块接口不变。

### 亮点 3：工单状态机

> "状态就三个：待处理、处理中、已解决。所有合法流转集中在一张 ALLOWED_TRANSITIONS 字典里，是全系统唯一的流转依据，判断逻辑只有一处，不会散落 if-else。非法流转直接拒绝返回 400，同时写一条 invalid_attempt 审计事件，配合事件流水表，每张工单'谁在什么时候做了什么'都可追溯。要扩展重开、转派，只是在字典里加一行，机制不变。"

### 加分项（主动提）

- **工程解耦**：LLM 有 Mock 实现，测试全程离线、稳定可重复；
- **配置外置**：模型、阈值全部 .env 可调，换模型不改代码；
- **取舍明确**：会话暂存放内存、API 无鉴权等简化是主动决策而非疏忽，能说出正式做法。
